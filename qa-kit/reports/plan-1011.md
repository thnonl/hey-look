## WP3 - macOS notifications via UNUserNotificationCenter
Branch `fix/v1011-mac-notify` d85ae56d, worktree `macnotify` with uncommitted edits (macnotify.rs +100, new state `quiet`, new string `settings.tray.macQuiet`, button "Open System Settings"). CI fails `-D warnings`: `State::Quiet` is only built under `cfg(any(test, target_os="macos"))` (`permission_state`), so the Windows/Linux non-test build sees it unused. Fix by cfg-gating the variant use or `#[cfg_attr(not(target_os="macos"), allow(dead_code))]` on the enum only; run `check-rust-warnings.mjs` for default + `qa-secrets`.
Known symptom: requests reach Notification Centre, no banner in front or in background. Coder checks, in this order, and logs each: (1) the delegate object is retained for the app lifetime (`UNUserNotificationCenter.delegate` is weak; a dropped Rust object = nil delegate = no `willPresent`); (2) delegate is set before `finishLaunching` (Tauri `setup` may be too late for a launch-by-click); (3) `willPresent` returns `.banner | .list | .sound` (macOS 11+), not deprecated `.alert`; (4) log `getNotificationSettings` `alertStyle`/`authorizationStatus` at every send (self-signed apps may get alert style None = the new `quiet` state); (5) Focus/Do Not Disturb noted in the report.
- AC-3.1 Send test with app in front: a banner appears (after Allow once). AC-3.2 New mail with app in background: banner with sender/subject; click opens the conversation. AC-3.3 Denied: no banner, toast names System Settings > Notifications. AC-3.4 Quiet (style None): the note `settings.tray.macQuiet` + Open System Settings shown; switching to Banners in macOS gives banners without restart. AC-3.5 Windows/Linux notification paths unchanged; CI green with `-D warnings`.
- QA: Mac only, rows A1-E1 of `E:\hey-mail\reports\v1-0-1\qa-mac-notify-1011-brief.md` plus Q1 (style None -> quiet note) and Q2 (log lines prove `willPresent` called).
