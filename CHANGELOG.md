# Changelog

## 1.0.11 — unreleased

### Added

- Settings > Mailboxes > Reading & sync has a switch for the automatic picture rule: "Show pictures automatically for people I have written to and for well-known services". It is on by default (as in 1.0.10) and applies to all mailboxes. With it off, pictures show without a click only from the senders whose pictures you chose to always show. While "Always show pictures" is on, the switch cannot be changed, because pictures from every sender are shown anyway
- In the same place, "Senders whose pictures are not shown automatically" lists the senders you turned off with "Stop showing pictures from this sender", with the date each one was added, a Remove button and a search box once the list is long. Removing a sender lets the automatic rule show their pictures again
- "Show the list of well-known services" shows the built-in list of services whose mail can show pictures automatically, with the number of services. A service counts only when the sender check passes (DMARC or a DKIM signature from the same domain). The list cannot be edited
- Compose: after you press Send, the message stays on screen, locked, until it has gone, in the main window as well as in a window of its own. Undo, or a send that fails, unlocks the same message where it is. When the message has been sent, a check mark and "Message sent" show for about a second, then the compose closes
- macOS: when macOS puts Hey Look!'s notifications in Notification Center without showing a banner, Settings > Notifications says so and has an "Open System Settings" button, so that you can choose Banners or Alerts for Hey Look!

### Fixed

- Pictures that give both a single address and a list of sizes (`srcset`) no longer show as broken after Show pictures, Show all pictures, "Always show pictures from this sender" or the automatic rule. Hey Look! now loads only the single address and leaves out the list of sizes and the extra sources of a `<picture>`. A picture that gives only a list of sizes uses its first entry and stays hidden, like any other picture, until you allow it
- A message you move or delete now shows up, and is counted, in the folder it went to at once, not only after the Undo time and the next sync
- Calendar: a calendar named after the account's address (such as the main Google calendar) shows that address once instead of twice
- macOS: notifications now work (new mail and Send test). Hey Look! shows them through the macOS notification system (UserNotifications) and asks macOS for permission at the first Send test or the first new-mail alert. Before, it used a method that recent macOS versions ignore, so nothing was shown. Send test also shows while Hey Look! is in front. If macOS refuses, the message gives the macOS reason ("Notifications are not allowed for this application") and points to System Settings > Notifications. Clicking a notification brings Hey Look! forward and opens the conversation. New-mail alerts are still skipped while a Hey Look! window is in front. Windows and Linux are unchanged
- The status line of an encrypted message in Compose reads more naturally, for example "Encrypted for you and 2 recipients. The subject is not encrypted." (English, German, Spanish, Japanese, Russian and Vietnamese)
- Spanish: the weekday letters above the small calendar are the Spanish ones, with X for Wednesday (before, the letters were lower case and Wednesday was "m")
- Russian: the name of a rule made for a sender no longer puts a case ending on the sender's name
- Vietnamese: Confidential mail is labelled "Bảo mật" instead of "Thư mật"
- Chinese: a space now separates Latin words (such as Hey Look!, Google or a domain) from the Chinese text around them
- Spanish: "Stop showing pictures from this sender" reads "Dejar de mostrar sus imágenes", and the hints of the rule values read "basta con que coincida una"

### Known limitations

- APT repository and Snap Store: not available in this release (download Hey Look! from GitHub or the website; it updates itself)
- Microsoft Store: Hey Look! is in the Store; the Store gets this release after Microsoft has approved it, so the Store version can be behind GitHub for a while
- Not tested by the project's QA with real accounts or real hardware; the owner checks these after the release and what he finds goes into the next version:
  - Google and Microsoft sign-in (mail and calendar) was tested with simulated sign-in servers, not with real Google or Microsoft accounts
  - Calendar: CalDAV sync was tested against simulated servers, not against real servers (iCloud, Fastmail, Baikal, Nextcloud, Radicale)
  - Confidential mail: hiding the window from screen capture (Windows Print Screen and Snipping Tool, macOS screenshots and screen recording) was not tested end to end with the real tools
  - The changes of 1.0.11 were tested on Windows 11 (on the computer itself, not in Windows Sandbox) and on an Apple silicon Mac (Apple M1 Pro, macOS 27.0.1), with debug builds of the 1.0.11 release candidate (on the Mac signed with a local test identity, not with the release signature) and with test mail servers instead of real mail accounts. Linux was not tested on this release (no Linux virtual machine could be started). On Windows every step was driven by test events through the test interface of the app, not by real mouse or keyboard input. On the Mac almost every step was driven the same way; real pointer input was used only to look at the Notifications page of System Settings (nothing was changed there) and to right-click a hidden picture (the menu opened and Show this picture loaded the picture; checked on an earlier build of the same release candidate). On macOS no notification banner was seen on screen, so whether banners appear was not tested, and the test of a banner while Hey Look! is in the background could not be run; with the notification permission turned off, the note in Settings (checked in Spanish) showed its text and the Open System Settings button. The downloadable macOS app and the Linux packages (AppImage, .deb, .rpm) were not installed or tested. Windows 10, Intel Macs and macOS 11 and 12 are supported but were not tested on this release, and neither were real sign-in, audible sound, the system's own tooltips on Windows and touch input.
  - Rules were tested with simulated mail servers, not with real Gmail, Outlook or iCloud mailboxes (Gmail labels in particular)
- Windows 11 puts the icon of a new app in the hidden-icons flyout of the notification area; to see it in the bar, drag it out or turn it on in Windows Settings > Personalization > Taskbar
- macOS: each pop-out window you close keeps a small empty system window (about 0.2 MB) until Hey Look! quits
- macOS: the first time you print, macOS may ask whether Hey Look! may find devices on your local network; the system print window asks it, to find your printers, and Hey Look! uses the local network for nothing else
- Confidential mail: Linux has no screenshot blocking (the window is hidden from screen capture and recording on Windows and macOS only)
- Linux: notification buttons need a desktop whose notification service draws them, and the tray icon has no click action (use Open Hey Look! in its menu)
- Linux: the x86_64 release packages (AppImage, .deb, .rpm) were not installed or tested
- Calendar: some work or school organisations only let an administrator approve the Microsoft calendar permission
- Rules: there is no "Mailing list" condition yet; a rule for all mailboxes that moves mail in several mailboxes gives one "moved" notice with Undo per mailbox
- There is no plain-text-only mode when writing a message
- Folders can be created but not renamed or deleted in Hey Look!

### Changed

- The text says "pictures" instead of "remote content" ("Show pictures", "Always show pictures from this sender", "Always show pictures" in Settings), in all eight languages
- Windows: starting Hey Look! with Windows now shows the window, like any other start. Before, it started hidden in the tray, and the hidden window could leave a white rectangle on the desktop. The window is made when the desktop is ready (taskbar, display and web view runtime), so it does not come up blank while Windows is still signing in
- Windows: the start-with-Windows entry of an existing install is rewritten at the first start of this version from `"<path>" --minimized` (or the older unquoted form) to `"<path>"`, so the update changes your next sign-in to a visible start. An entry of another program and one that you turned off in Task Manager are left alone
- The new-mail notification sound is quieter (9 dB lower, same sound)

### Added

- Pictures show without a click in messages from people you have written to (any of your mailboxes) and from a built-in list of well-known services (for example Google, Microsoft, Apple, Amazon, GitHub), but only when the message passes the sender check (the result your mail provider writes into the message), and never in Junk, in encrypted messages or after a failed check. An info button in the message header says why and offers "Stop showing pictures from this sender" (with Undo) for that exact address; Settings has no list of the senders turned off yet
- A hidden picture is now a visible box with a shield, "Picture hidden for privacy" and how to show it. Click it, press Enter, or right-click it (Shift+F10 with the keyboard) for "Show this picture", "Show all pictures in this message" and "Always show pictures from this sender"
- The app now ships its own font (Inter) so that text looks and wraps the same on Windows, macOS and Linux (Chinese and Japanese keep the system fonts; the font adds about 57 KB to the app)
- Senders whose pictures are always shown: a link in the notice above a message whose pictures are hidden, "Always show pictures from this sender", shows them at once and for every later message from that exact address (not in Junk, not for encrypted messages, not when the sender check failed, never for your own addresses). "Stop showing pictures from this sender" is in the same place, with Undo. The list is in Settings > Mailboxes > Reading & sync, with search, Remove and Remove all; Block sender takes the address off it
- Hey Look! is also available in the Microsoft Store (a link on the download page and in the README); the Store installs it and keeps it up to date
- Windows: Settings > Notifications has a new switch, "Start in the tray", under "Start Hey Look! when I sign in to Windows" (shown while that one is on; off by default; in all eight languages). Turning it on makes the entry `"<path>" --minimized` again: the app starts in the tray icon and the window stays hidden until you open it. Turning it off, or the start-with-Windows switch off, writes the entry at once
- Windows: a line under the switch "Start in the tray" says that with it on Hey Look! starts with its window closed and is opened from the tray icon
- `startup.log` has `[autostart]` lines that say which entry is registered and whether "Start in the tray" is on, and a `[gate]` line that says when a start is treated as a start at sign-in
- Account menu has "Account settings…"; One Inbox has a menu with "All accounts settings…"
- Mailboxes can be reordered by dragging the whole header row, the avatar in the narrow icon column or the Settings entry (touch: the grip only)
- Settings > Add account > iCloud, Yahoo, other: a Test connection button checks the incoming (IMAP) and outgoing (SMTP) server at the same time without saving anything, and says per server what is wrong and which field to fix (server name, port and security, certificate, password or app password), with one-click fixes for common mistakes (port and security, swapped hosts, trusting a certificate, an app password link, Google or Microsoft sign-in). A failed Add account shows the same lines (in all eight languages)

### Fixed

- The first message that arrives in a new account whose Inbox was empty now gives a notification (before, the first message was taken for part of the first sync and had none)
- The preview text of a message (in the list and in the notification) is plain words: the alt text of pictures ("[image: Google]", "[cid:...]"), link addresses and the words that pointed at an address ("at", "see", "visit") are left out; the message itself is not changed, and previews saved before are cleaned once
- With animations turned off in the system, the emoji picker's search box did not get the keyboard focus when it opened
- Windows: when Hey Look! cannot start because its data folder or the web view's folder cannot be used (a file where the folder should be, no permission to write), the message now names the folder and what Windows said, in your language, instead of blaming the Microsoft WebView2 Runtime, and it is shown before the web view makes its own English message; a missing runtime keeps its message
- Windows: a start in the tray no longer takes the keyboard focus for a moment while the hidden window is made, so what you are typing at sign-in is not interrupted
- Windows: turning on "Start Hey Look! when I sign in to Windows" is written to your own user's startup entry and read back. Before, a copy that ran as an administrator wrote the entry for all users, the switch showed "on" and your own entry was missing; now a failure turns the switch back off and shows the Windows error
- One Inbox always stays in Favorites (and is restored if it was removed); its star is gone
- Clicking the open message again no longer reloads it: the reading pane, loaded pictures and expanded messages stay
- The highlight of a found setting in Settings no longer covers the text of the setting
- macOS: Ctrl+click on a mailbox header no longer also collapses it, and a right-click on the left edge of an avatar in the icon column opens the account menu without opening the sidebar

## 1.0.8 — 2026-10-25

### Added

- Rules (called Filters until now): right-click a message > "Create rule…" (also in the More menus of the reading pane and the message window, in the command bar and, for all rules, "Manage rules…" in the menu of a mailbox) opens a dialog with the sender, the subject and up to five suggested words from the message already filled in, in all eight languages. A rule can have several conditions (all must match; From, To, Subject, Body, or Subject or body; any of several words), can look in the body of a message (the first 20,000 characters; never for encrypted or Confidential mail), and can move the mail to a folder you pick or make there ("New folder…"), archive it, delete it, send it to Junk, mark it as read, flag it or pin it
- Rules run in the order of the list in Settings > Rules (Move up, Move down); the first rule that moves a message wins, and the rules that only mark it (read, flag, pin) still run. "Also move the messages already there" in the dialog, and "Run now" in Settings > Rules, apply a rule to the mail that is already in the folder (the newest 5,000 messages): the count is shown first, the move has the Undo time like any move, and "Undo" brings the mail back

### Changed

- "Filters" are called "Rules" in Settings (and in Settings search, where "filter" still finds them), the help text on the website and the README, in all eight languages. Rules you made before keep working

### Fixed

- Windows: after an in-app update the new window could stay white (no taskbar button) until you clicked the tray icon. The cause could not be reproduced, so the safety net was widened: every check of a new window now reads the screen for up to 30 seconds (it stopped after 3 seconds), a window that no check has found painted is checked again whenever it is shown (a click on the tray icon, a second start of the app, a notification) and asked once to redraw, and `startup.log` keeps the start of its run when it is cut at its size limit and its first line says how the process was started. If a white window comes back after an update, the first lines of `startup.log` in the data folder of the app tell how it started and what the checks saw
- Reply, Reply all and Forward show the pictures of the original message when Settings > Reading > Load remote content is on (a picture could not load there: empty boxes); when it is off they show the same boxes as the reading pane with a "Load content" button. Pictures from the web are still fetched by Hey Look! and never by the window, and the message you send is unchanged
- The name of the mailbox is on a line of its own above the Focused and Other tabs (it sat too close to the underline of the tabs); it has a tooltip with the full name and address
- "Loading…" no longer shows for ever under Filter: Flagged or Unread (and in the Unread view, or a Focused or Other tab with few messages) when the older mail that is read has nothing for the filter: the reading stops after a few requests and the end of the list has a "Load older messages" button; when a request fails the list says why, with a Retry button
- A list of "Saved info" from the browser (earlier searches) no longer opens over the search panel on Windows: the browser's autofill and password saving are off in every window of the app, and every text field says it wants no autocomplete. The entries the browser has already stored are not deleted, they are not offered
- A message you move (by hand, by drag or by a rule) shows in the folder it was moved to at once: Hey Look! reads that mailbox as soon as the move is done, instead of at the next sync, which could be two minutes later (in the meantime the message was in neither list)
- Rules and new-mail notifications work after the Inbox was emptied (Archive all, Run now): a sync of an Inbox with no mail on this computer was taken for the first sync and its mail was left alone; the highest message number the app has seen in each folder is remembered now
- Rules: "To is exactly" matches a message sent to several people when one of them is the address; a message you put back into the Inbox (Undo, Move to Inbox, drag) is not moved again by the rule that moved it out; a second move rule no longer marks the wrong folder as the one with new mail,; a second message of a conversation that was already moved is not moved again; mail from a blocked sender is not ruled

## 1.0.7 — 2026-10-25

### Added

- macOS: the menu bar has the standard items of a Mac mail app: Hey Look! > Settings… (Cmd+,), File > Print… (Cmd+P, on while the window with the focus shows a message you can print; off for Confidential mail, a message being written and Settings) and Help > Hey Look! Help (the help page in the language of the app). They follow the language of the app at once. The first time you print, macOS may ask about the local network (the print window looks for printers); the question now says why, in the 8 languages of the app.
- Linux: a new-mail notification has the buttons of the mailbox's Notifications > Buttons setting (Archive, Delete, Mark as read by default) when the desktop's notification service draws buttons, and a click on the notification opens the conversation; a button works also while the window is hidden. Settings says so when the desktop has no buttons.
- macOS: Print is in the More menu of a message (main window and message window) and Cmd+P prints in a message window; the system print sheet opens on that window with the message only, in the light colours, across as many pages as it needs.
- Linux: with the theme set to System the app follows the desktop's light or dark setting (read from the desktop portal, or from the GTK settings when there is no portal), also while it runs; the title bar, scroll bars and pop-up lists of the system follow too. Light and Dark chosen in Settings still win.
- A PDF attachment is drawn in the preview on macOS and Linux too (until now a card with Open and Save as): the pages with their text (select and copy, read by a screen reader), "Page 3 of 30" and zoom (Fit, 100 %, 150 %, 200 %) in the header, Esc and the arrows as for a picture. Links inside a PDF do nothing and nothing in a PDF runs; a PDF with a password says so, and one that cannot be drawn shows Open. The viewer is PDF.js (Apache-2.0, with its fonts, character maps and decoders; the licences are in the app's `pdfjs` folder) and loads when the first PDF is previewed. Windows is unchanged (the system's own viewer).

## 1.0.6 — 2026-10-18

Writing a message got much more complete and much safer, and messages can now be written and read in windows of their own. Nothing you write is lost to a crash any more, the message that goes out is built the way other mail programs build theirs, and the mail list, the mailboxes, the side menu and the AI Assistant got a number of long-wanted touches.

- Right-click menus: on a conversation in the mail list, and on text anywhere in the app
- Mailboxes: your own order and a Display name

### Fixed

- Adding an IMAP account whose server accepts the connection and then says nothing (for example a port that does not speak IMAP, with STARTTLS) now shows the secure-connection hint after at most 20 seconds, as for SMTP. Before it waited about 80 seconds and said “The mail server did not respond”
- Linux: saving an attachment when the Downloads folder is missing (never created, or moved away) now creates it; if that is not possible, or the folder cannot be written to, the files go to your home folder and Hey Look! says so. Before, the save failed with “No such file or directory”
