# Changelog

## 1.0.6 — 2026-10-16

Writing a message got safer and more complete: nothing you write is lost to a crash any more, Bcc, names and Reply-To are kept, and the message that goes out is built the way other mail programs build theirs. The mail list, the mailboxes and the top bar got a few long-wanted touches.

### Added

- Writing a message: a fuller formatting toolbar in one row (more controls move into a More menu when the window is narrow): font, font size, strikethrough, subscript and superscript, font colour and text highlight colour with the Office palette (recent colours are remembered), clear all formatting, Undo and Redo. Keys: Ctrl+] and Ctrl+[ change the font size, Ctrl+= and Ctrl+Shift+= subscript and superscript, Ctrl+Space or Ctrl+\ clear the formatting, Alt+F10 goes to the toolbar. The signature and template editors have the same toolbar
- Writing a message: paragraph formatting in the toolbar and by keyboard: align left, centre, right or justify (Ctrl+L, Ctrl+E, Ctrl+R, Ctrl+Shift+J), increase and decrease indent (Ctrl+T, Ctrl+Shift+T), line spacing and space after a paragraph (in the More menu), bulleted lists (filled circle, hollow circle, filled square) and numbered lists (1. a. A. i. I.) with a style menu on each button, a Styles menu (Normal, Heading 1 to 3, Quote, Code; Ctrl+Shift+S, Ctrl+Shift+N, Ctrl+Alt+1 to 3) and a horizontal line. The font size box is now a box you can type a size into (Enter applies it) as well as a list. Everything is sent as plain inline formatting that other mail programs show the same way, and a draft you reopen is the same message
- Writing a message: pasting from Word, Excel, Outlook, Gmail, Google Docs, web pages and Apple programs is cleaned (Word's typed numbers and bullets become real lists with their levels, no Word styles, scripts, forms or pictures from the web are brought in) and a small Paste options button after the paste lets you switch the same paste between Keep source formatting, Merge formatting (takes the font around the cursor) and Keep text only; open it with a click or by pressing and releasing Ctrl. Ctrl+Shift+V always pastes text only, a drop of text from another program is cleaned the same way, and Settings > Composing > When pasting from other apps sets what Ctrl+V does. A table pasted from Excel or Word becomes one line per row with the cells apart by a tab until tables come to the editor
- Settings > Composing > Default font: the font and size new messages, replies and forwards start in (Calibri 11 pt). The message is sent with that font and without extra space between paragraphs, so the recipient sees what you saw; a saved draft keeps the font it was written in
- Mail list: right-click a conversation (or press the Menu key or Shift+F10) for a menu with Reply, Reply all, Forward, Mark read or unread, Flag, Pin, Snooze, Move to, Archive, Delete, Move to Junk, Copy sender email and Copy subject. With several conversations ticked, it works on all of them
- Reading: double-click a conversation (or press Shift+Enter on it, use Open in new window in its right-click menu, the button above the message or the command bar) to read it in a window of its own, with Reply, Reply all, Forward, Archive, Delete, Flag, Mark as unread, Snooze, Summarize and Translate. Mail you archive, delete or flag in the window is done by the main window (with its Undo), the window shows a notice when the conversation was moved or deleted elsewhere, and its size and place are remembered for the next one. Up to 8 windows can be open
- Writing a message in a window of its own: hold Shift when you click New mail, Reply, Reply all or Forward (or press Shift+C, R, A or F), double-click a draft in Drafts, or use the Pop out button (Ctrl+Shift+O) in the message you are writing. Settings > Composing > "Open new messages, replies and forwards in a separate window" makes that the normal way, and Shift then does the opposite. The window shows the subject in its title bar, remembers its size and place, and keeps working when the main window is in the tray. Send shows "Sending… n s" with an Undo button in the window; closing the window then still sends the message at the end of the Undo time. Closing a window with a message asks Save, Discard or Cancel; an empty one closes at once. Quitting or updating saves every window's message to Drafts first. A message written in a window comes back in a window after a crash. The same draft is never open in two windows
- Mailboxes: drag a mailbox in the folder pane or in Settings to put them in the order you like, or use Alt+Up and Alt+Down (also in the right-click menu of a mailbox). The order is kept
- Mailboxes: the Display name of a mailbox is shown in the folder pane, the list header and the command bar instead of the address; the address is in the tooltip
- Importance: when you write a message you can mark it High or Low (two buttons next to Confidential). The message carries the importance headers other mail programs understand. High and Low mail you receive shows a red "!" or a blue arrow in the list and a label in the reading pane. Mail that was already downloaded before this version shows no mark
- Writing a message: Preview as recipient (Light / Dark) in the formatting toolbar shows how the message looks on a light or a dark background. It does not change what is sent
- In the dark theme the top bar is tinted by the primary colour you chose in Settings > Appearance (it was always the same dark grey)
- The browser's own right-click menu is no longer shown in the app. In text fields (the message you write, the search box, every setting) the usual menu with spelling suggestions, Cut, Copy and Paste stays. Anywhere else on text (a message you read, its header, a dialog, a notification) right-click for Copy and Select all, and Copy email address when the pointer is on an address (also on a recipient and on the sender). Links in a mail have Open link and Copy link address. The Menu key and Shift+F10 open the same menus at the selection or the focused link, and the arrow keys and Esc work in them, in the main window and in the extra windows
- Writing a message: the message is saved to Drafts by itself about every 30 seconds while you change it (the same draft is replaced, never doubled), and a copy is kept on your computer every few seconds. If the app ends unexpectedly, the next start asks "Restore your unsaved message?" with Restore, Discard and Not now
- Writing a message: the Insert part of the formatting toolbar. Table: pick the size on a 10 x 8 grid or in Insert table... (1 to 20 columns, 1 to 100 rows); floating table tools for rows, columns, borders (all, outside, none), cell shading and a header row; Tab goes from cell to cell and adds a row at the end (Esc then Tab leaves the table). Tables pasted from Word, Excel or a web page stay tables, with their shading and borders. Links: Ctrl+K, a small bubble under the link the caret is in (Open link, Edit link, Remove link), Ctrl+click opens a link, a plain click only places the caret. Pictures: align left, centre or right, put a link on a picture, drag a corner handle to resize it. Emoji: a picker in the Insert menu (the system's own panel is named under it).
- Writing a message: Reply and Forward quote the original message in a block of its own that keeps the original's look (fonts, colours, tables, lists, alignment, right-to-left text, pictures), below your text and your signature, with the line "On <date>, <name> wrote:" (or the forward header) above it. The block cannot be broken by accident: typing, pasting and Enter while it is selected go below it, Backspace and Delete next to it leave it alone, and clicking it and pressing Delete removes it (Ctrl+Z brings it back). "Edit quoted text" (after a question) turns it into ordinary text you can change; Hide / Show and Remove are next to it. Pictures from the web are not loaded while you write (they stay in the message you send), scripts, forms, event handlers and external styles are removed, and pictures inside the original travel with the reply. The block is saved with the draft and is the same after reopening it or restoring after a crash; a very large original (more than about 1.5 MB of HTML) is quoted as plain text. In the plain-text part every quoted line starts with "> ".
- AI Assistant: when Summarize, Translate or Write with AI cannot work, a message now stays on screen until you close it (the X, or Esc while it has the focus) and says what happened and what to do: the Assistant is not set up yet, the provider rejected the key, the address could not be reached, the model name was not found, the provider is busy, the answer could not be read, or it took too long. Its button Open AI Assistant settings opens Settings on the AI Assistant tab with the cursor in the field the problem is about (API key, Base URL or Model), also from a message window or a writing window; Try again is there where trying again can help. Cancelling a call shows nothing. Before, Summarize and Write with AI opened Settings without a word, and a failed call showed one line of error with no hint where to fix it

### Fixed

- Writing a message at the smallest window size (the main window at 960 x 560, or the window of its own at its smallest): the formatting row and the message body are always in view and the body keeps room for about eight lines; before, the rows of buttons and fields filled the whole pane and pushed both out of view. When the pane is narrow or low the actions are one row of icons (Send, Discard, Attach) with a More actions menu for the rest, the fields above the message scroll instead of pushing it out, and many recipients or attachments get a box of their own with a scroll bar. The suggestions, the Send later popover and the Sign menu are no longer cut off by the scrolling fields, and the Signature picker no longer runs out of a narrow pane
- Mac: Cmd+Shift+V pastes the clipboard as plain text in the message you write (and in the signature and template editors, also in a window of its own); it pasted nothing before. In a text box such as To or Subject it pastes the text too. Cmd+V, Cmd+C, Cmd+X and Cmd+A are unchanged
- Writing a message: after pasting formatted text and choosing Keep text only or Merge formatting in the Paste options, the text no longer stays bold when it was pasted at the start of a paragraph, and what you type next continues in the format you had before the paste
- Drafts: the Bcc recipients are kept in a saved draft and come back when you reopen it. Before, a draft opened again and sent went out without them
- Drafts: when you reopen a draft, the display names of To, Cc and Bcc are kept
- Drafts: saving or sending a draft removes only that draft, not every draft of the conversation or a version saved in another mail program
- The copy in the Sent folder is exactly the message that was sent (it was two bytes shorter)
- Reply goes to the Reply-To address of the message when there is one, and says so under To (with a button to reply to the sender instead); Reply all adds the other people without repeating anyone, and your own addresses are left out
- Writing a message: the size limit of the mail server is asked when a message opens and when files are added (it used to be asked only above 8 MB, so a server that takes 5 MB was never found). Send is stopped with the size of the message and the limit of your server, and a message the server still refuses says the same
- Reply and Reply all keep the display name of the sender and of the people in To and Cc, also when it has a comma ("Doe, John")
- Reply and Forward no longer flatten the original: a table, the colours, fonts, lists and alignment of the message you answer arrive as they were (before, a table became one line of text and the colours were lost)
- Writing a message: a person is in one of To, Cc and Bcc only (the first one that has them); an address added again in a later field is not added and a note says where it already is
- Forward carries the attachments of the original message (you can remove them before sending); pictures in the text stay in the text
- Recipients: an address with a quoted name such as "Doe, John" <john@example.com> stays one recipient, also when pasted or dropped, and a list copied from a spreadsheet becomes one recipient per row
- Recipients: the Enter key that confirms a conversion with a Japanese, Chinese or Korean input method no longer creates a recipient
- Messages you send have their own Message-ID with your address domain (not the name of your computer), and the copy in Sent has the same one, so replies are linked to the right conversation
- A message with only Bcc recipients can be sent (the To line then reads "undisclosed-recipients")
- Long lists of recipients and long References are wrapped to 78 characters per line in the header, as the standard asks
- The greeting the app sends to the mail server (EHLO) no longer contains the name of your computer
- The plain-text version of a message keeps links as "text (address)", bullets and numbers, quotes and tables, so mail programs that show text only read it properly
- An address that appears twice (also in To and Cc, or in different upper and lower case) is only sent to once
- Pasting from a web page: pictures from the web are no longer fetched while you write (they are not pasted, with a short notice), and pictures that point to a file or a network path (\server\share) are never sent as picture sources
- The header lines of a reply and of a forward (sender, subject, recipients) are shown as text, even when a name or subject contains markup
- Ctrl+1 and Ctrl+2 with a button of the message toolbar selected no longer switches away and blanks the message you are writing
- Attachments: the size is counted as it is sent (about a third more than the files), and the limit of your mail server is used when it tells one, so a message the server would refuse is stopped before sending with the real numbers
- Attachments: file names are cleaned before sending (no folder part, no hidden or control characters, no reserved Windows names, a sensible length) and two files that end up with the same name get a number
- Links: Insert link (button or Ctrl+K) opens a small dialog in the app with the address and an optional text, instead of the system prompt; Remove link is in it too
- Writing a message: Report and Snooze (and every other button that needs a selected mail) are greyed out while a message is open and no mail is selected
- macOS: the app is now signed with a fixed certificate (self-signed, not notarized), so macOS keeps remembering which app may read your saved passwords across updates. Because the signature changes once, the first start after updating to this version asks about your saved passwords one more time
- Quit: Quit always ends. The app waits at most 8 seconds for a window that does not answer, 45 seconds for one that is saving or sending, and 60 seconds for a question to you ("Quit and discard?"), and then quits; the message you were writing is kept as a recovery copy and a message in its Undo time goes out at the next start. A question that has to be answered is shown in front, also when the window was hidden in the tray. If the app is still alive 40 seconds after the quit began, it is ended
- Linux: when the window comes back from the tray ("Open Hey Look!") the app checks that the page still runs and loads it again when it does not, instead of leaving a blank page; a web view process that ends is loaded again at once. On Linux the tray icon has no click action (the desktop's indicator service does not pass clicks on): use "Open Hey Look!" in its menu
- Translate: a long email is translated in full (up to 60,000 characters) instead of only its first 12,000: the text is cut at paragraphs, then at sentences, into parts of about 8,000 characters that are translated one after the other and put together in the layout of the original. The notice and the box say "Part 2 of 5"; Cancel stops the request and the parts not yet started; a part that fails on the network or with a 5xx answer is tried once more, and when it still fails, Retry goes on from that part without translating the finished parts again. Beyond 60,000 characters the first part is translated and a note says so
- Summarize and Write with AI: both show that they are running and have a Cancel button (it drops the request to the provider); a second click while one is running starts nothing, and an answer that arrives after Cancel, or after you moved to another conversation or closed the message, is ignored
- AI Assistant errors: an answer the app cannot read is now one sentence in your language, not the raw reply of the provider; an error about the connection no longer shows a password or a token that is part of the address in Settings
- Attachments: the preview of a PDF shows the PDF on Windows again (it was a blank "blocked" page since the Windows web view does not run its PDF viewer inside a restricted frame). Only a file that really is a PDF is drawn; a file called .pdf that holds anything else says so and can still be opened or saved. A link inside a PDF no longer takes the whole app window to a web page
- Attachments: the preview of a PDF shows the PDF on a Mac too (it stayed blank white there). If a preview cannot be drawn, the dialog now says so and offers Open with your default app instead of showing an empty page. A link inside a PDF no longer takes the app window to a website on Windows or on a Mac; it does nothing.
- Windows of their own (Mac): closing a window of its own is now done in steps the log shows (hidden, destroy scheduled, gone), a window that is closed before its page is up is never shown, a second open of the same conversation or draft while its window is still being made no longer shows a blank window, and two quick clicks on the same thing open one window. The log also says how many windows are left after one closes, and finishes the native window by hand, so a closed window does not stay listed by macOS.
- Start: when the app cannot start at all on Windows (for example the Microsoft WebView2 Runtime is missing or damaged) it now says so in a message in the language of Windows, with where to get the runtime and where the log file is, instead of closing without a word; macOS and Linux write the reason to the same log file
- Settings > AI Assistant no longer jumps while you use it: "Loading models…" and the messages about the model list have a fixed place under Save (they used to be inserted above it and pushed Save down and back on every key you typed), "Remove the saved key" is on the line of the API key label (it used to appear under the box after Save and move everything), the Model box keeps its focus and cursor when the model list arrives, and Remove the saved key leaves the focus in the API key box
- The preview of an attachment (PDF, picture, text) and the picture viewer open on top of the whole window. In a conversation with several messages the Reply, Reply all and Forward buttons of the later messages were drawn over the preview, and the picture viewer opened inside the message instead of over the window. The focus now moves into them, Tab stays inside, and Esc gives the focus back to the attachment
- Settings > Add account (Google, Microsoft and other accounts) and Settings > mailbox > Calendar no longer jump during a sign-in: "Waiting for your browser", the notice that the sign-in ended, an error and the hint for a button that is off take turns in one place of fixed size under the button (they were rows inserted above and below it, so the button moved away from the pointer; the calendar's status line grew and shrank under Sync now). When a sign-in ends, the focus goes back to the button that started it
- Settings > AI Assistant: when saving fails (a locked key store, a file that cannot be written) the reason is now shown under Save, in all languages, and what you typed stays in the boxes. Before, nothing was shown. The same for Remove the saved key

## 1.0.5 — 2026-10-16

A few leftovers from 1.0.4: Cancel on an AI request, error messages that pile up, a mail that turns read after a failed Archive, the Junk folder and the 404 page of the website.

### Fixed

- Notifications and the mail list no longer show link markup from marketing mail: a plain-text part that starts with "[View in browser](https://...tracking address...)" gave a notification (and a list row) full of that text. Markdown links now show their text, "View in browser", "Unsubscribe", "Click here" and their translations are left out, and addresses, tracking tokens, image and reference markers, HTML entities and invisible characters are removed. When little readable text is left, the notification shows the sender and the subject only; the preview line is cut at about 100 characters on a word, never inside an emoji or a letter with accents. Mail already in the list is cleaned once at the next start; search still finds every word and address of the message
- Translate: Cancel now stops the request to the AI provider, not only the waiting, so a cancelled translation no longer keeps running (and costing tokens) in the background
- Many failed translations no longer cover the mail list and the reading pane: at most three notices of the same kind stay on screen, the rest are folded into one "more notifications" row with Dismiss all
- The notices about a translation (running, ready, failed) follow the language you choose, also when you change the language while they are on screen
- Archive and Delete: when the move is refused or you press Undo, the next mail that Hey Look! opened for you goes back to unread, if you did nothing with it in the first 10 seconds, and the selection returns to the mail you moved
- Junk: the Junk folder and the actions that move mail to Junk (Move to Junk, Block sender, the ! key) are hidden or greyed out, with the hint "No Junk folder", when the mailbox has no Junk folder. Archive and Trash stay, they are created when you first use them
- Updates: the "new version available" notice now appears when you start the app or come back to its window, also within a few hours of an earlier check, on every system. Before, a check that found nothing new made the app skip the next ones for 6 hours (1 hour after a failure), even after quitting and starting it again, and only Settings > About found the update (seen on a Mac, where the app stays open for days). Now starting the app checks again when the last check is 5 minutes old, and coming back to the window after 2 hours (15 minutes after a failed check). A busy or broken answer from GitHub (for example HTTP 429 or 500) is no longer taken for "no release": the update the app already knows stays and the check is repeated soon. The log (startup.log) now says, for every check, whether it asked the server or why not, and why a notice did not appear
- Writing a message: when you click another mail (or open one with the keyboard, a notification, a search result or the calendar) the message you are writing closes instead of staying in the way. An empty message is dropped; a message with text is saved to Drafts first and a Draft saved notice with Edit brings it back. If saving fails, the message stays open and your text is kept. While you write, no mail is selected in the list, so the buttons and keys for the selected mail (Archive, Delete, Flag and the others) cannot act on a mail you are not looking at
- Pasting a picture into a message: the small toolbar under the picture (Small, Medium, Large, Original, Alt text, As attachment, delete) no longer draws the Alt text label over As attachment, in any language or window width. Deleting the only picture no longer leaves a message you cannot type in, and Backspace under the signature no longer moves the signature block down: the signature stays in its place
- Writing a message: Ctrl+Shift+B only adds the Bcc field (it also turned the paragraph into a quote), Ctrl+K (Cmd+K on a Mac) in the text adds or edits a link, AltGr keys on German, Polish and other keyboards type their characters (@  { [ ] } | ~ €) instead of changing the paragraph into a heading, and Ctrl+Enter only sends (it also added a line break)
- Website: the 404 page (page not found) is written in the language of the address in all eight languages, including the top menu and the footer
- Website: "No ads" now stands next to "Free" and "No account" (home page, comparison table, features, download page, footer) in all eight languages
- Website: the live preview of the Appearance choices with Reading pane = Bottom no longer squeezes the mail rows on top of each other; the list scrolls, Compact is one line like in the app, and the folder column and long messages fit at every text size and window width

## 1.0.4 — 2026-10-16

Small fixes found while testing 1.0.3: event times, Archive and Delete errors, quick clicks on flag and pin, long texts in Settings, the macOS app menu and the website on phones.

### Fixed

- New event, Edit event and the meeting strip in a new message: when you change the start date or time, the end now moves with it and keeps the length of the event (an all-day event follows by days). Changing the end never moves the start; an end before the start is still refused when you save
- Archive, Delete, Junk and Move: Hey Look! now checks the target folder before it moves the mail. A missing Archive or Trash is created again where the server allows it. When the folder cannot be found or created (also when it was removed on the server after the last sync), the mail stays where it is, the "Archived" message goes away and the error shows within a moment. Before, "Archived" and Undo appeared first and the error came about 7 seconds later. Junk and other folders are looked up but never created
- Flag and Pin: pressing the button several times quickly now ends in the state of your last click and stays there, as Mark read and Mark unread already do
- Settings: long texts are no longer cut off with an ellipsis in any of the eight languages at a 960 px or 1280 px window (for example the default account in Russian, the Notifications choices and the PGP key list)
- macOS: About, Services, Hide, Hide Others and Show All in the app menu now follow the language you chose, like Quit; Show All is new
- Windows: when Windows refuses to show a notification, Hey Look! no longer hides the error. Send test in Settings > Notifications shows it, and the log (startup.log) gets a line saying the notification failed
- Translate (More actions > Translate to ...): a long email no longer looks as if nothing happens. A notice with a spinner and a Cancel button stays on screen until the translation arrives, and the message shows a Translating box (with the time that has passed) where the translation will appear. The translation goes on when you open other mail or folders; when it is ready while you are elsewhere, a notice with Show takes you back to the mail. An error (no answer within 180 seconds, a provider error, no API key) replaces the spinner and offers Retry. The AI Assistant no longer waits for ever for an answer
- AI Assistant: when the AI provider answers with an error, the message now says it in one short sentence, in your language, with the provider’s own words when it gave a readable reason (for example “The AI Assistant returned an error (503): upstream overloaded”), instead of the raw answer of the server
- Translate: the notice with the timer and Cancel no longer squeezes a long sentence (for example in German) into three lines in a narrow reading pane; the timer and Cancel move to their own line instead
- Test copies of Hey Look! (builds run on a separate data folder) no longer share the AI key, passwords and notification icon of the installed app: they use their own credential store name and notification id
- Website: the logo keeps its size on phones, the top menu folds into the menu button before it can touch the buttons, long German words no longer run off the page, and the Theme and Animations buttons are described with whole sentences in every language

## 1.0.3 — 2026-10-16

Hey Look! now speaks eight languages, dates and times have their own pickers, and more bugs found in testing are fixed.

### Added

- Languages: five more languages for the app, so there are now eight: English, Tiếng Việt, Français, 中文（简体）, Español, 日本語, Deutsch and Русский. English stays the default, and the language is always the one you choose; it is never taken from your computer’s language. Dates, times, the tray menu and notifications follow it. The new texts were written with AI help and have not been reviewed by native speakers yet, so they may contain mistakes
- The website is translated into all eight languages too: English at the root and one folder per language (`/vi/`, `/fr/`, `/zh/`, `/es/`, `/ja/`, `/de/`, `/ru/`), with a language menu on every page
- Date and time fields: the New event dialog, the meeting strip, Send later and the search filters no longer use the browser’s own date and time boxes. You type a date or time the way your language writes it, or pick it from a month grid or a time list; times follow the 12 or 24 hour setting of Settings > General
- A small support reminder: about once every two months (the first one 1 to 4 weeks after you start using Hey Look!, and six months after you press “Buy me a coffee”) a note says you can support the project. It waits for a calm moment (never while you write a message, with a dialog open, or while something is sending or downloading), goes away by itself after 15 seconds, and stays on this computer. Press “Don’t remind me again” on it, or turn off Settings > General > Occasional support reminder

### Fixed

- Adding an IMAP account whose server accepts the connection and then says nothing (for example a port that does not speak IMAP, with STARTTLS) now shows the secure-connection hint after at most 20 seconds, as for SMTP. Before it waited about 80 seconds and said “The mail server did not respond”
- Linux: saving an attachment when the Downloads folder is missing (never created, or moved away) now creates it; if that is not possible, or the folder cannot be written to, the files go to your home folder and Hey Look! says so. Before, the save failed with “No such file or directory”
- Update restart: when you press Restart now while a message is open and it cannot be saved to Drafts, a question now asks what to do: Keep writing (nothing restarts) or Restart and discard. After a discard the update toast no longer says the message is in Drafts
- Folders: a server folder is taken for the Sent, Drafts, Archive, Trash or Junk folder when the server flags it, or when its whole name is a standard one (English, German, French, Spanish, Italian, Portuguese, Vietnamese) at the top level or directly under INBOX. A folder such as `Trash-old`, `Archive 2019` or one inside another folder (`Old/Trash`) is no longer mistaken for it, and a flagged folder is no longer passed over for a plain one with a similar name
- Sending: when the server has no Sent folder, Hey Look! now creates one (where the server allows it) and keeps the copy of the sent message there. The send itself, Undo and Send later are unchanged
- The Send later popup stays inside the window when the window is 960 px wide or narrower: it moves sideways, scrolls when the window is short, and its buttons wrap
- Spanish: the Inbox folder is called “Recibidos” (as in Gmail and Apple Mail), so the name fits the folder list
- Mark read / Mark unread: pressing the button several times quickly now ends in the state of your last click and stays there. Before, the mail could keep switching between read and unread for a moment after you stopped clicking
- Moving quickly from one unread mail to the next no longer turns a mail you just opened back to unread a moment later: the mail list now ignores a refresh that was started before your last change

## 1.0.2 — 2026-10-15

Fixes for the mail list, the reading pane and Archive / Delete.

### Fixed

- With the Unread filter on, the mail you are reading no longer disappears from the reading pane (“Select an item to read”) a few seconds after it is marked read. The same happened under the Flagged filter when you unflagged the open mail (since 1.0.0)
- Archive and Delete now work when the server has no Archive or Trash folder, or one that appeared or was renamed after the last check: Hey Look! looks at the server, creates a missing Archive or Trash (where the server allows it) and moves the mail. If the folder cannot be found or created, the mail stays where it is and an error says so. Before, the mail was only hidden for a moment and came back, and the error showed after the success message; the action then kept failing until the next restart or sync (since 1.0.0)
- A filtered mail list (for example Unread with a few mails) no longer ends with “Download limit reached (500 mails per mailbox)”; that notice now appears only under an unfiltered folder that really reached the limit (since 1.0.0)

## 1.0.1 — 2026-10-15

New Inbox mail now arrives at once, Hey Look! speaks Vietnamese and French, and your Google and Outlook calendars can sync. Several bugs found in testing are fixed.

### Added

- Push mail: new Inbox mail arrives at once on servers that support IMAP IDLE (the account’s Server settings say Push or Polling). Servers without it, and the other folders, are checked as before at your interval (every 10 minutes while push works). Settings > Mailboxes > Reading & sync has a switch to turn push off
- Calendar: turn on two-way sync with Google Calendar or Outlook / Microsoft 365 (Outlook.com, Hotmail, work and school accounts) for a mailbox (Settings > Mailboxes > your mailbox > Calendar). Repeating events from those calendars are shown but can’t be changed in Hey Look! yet
- Languages: the whole app is now available in English, Vietnamese (Tiếng Việt) and French (Français). Choose it with the globe button in the header, on the Welcome screen or in Settings > General > Language; English stays the default. Dates, times, numbers, the tray menu and notifications follow the language too. The Vietnamese and French texts have not been reviewed by native speakers yet
- A button in the reading pane switches a mail between its original background and a dark one; your choice is remembered
- macOS: the Dock icon shows the unread number (the same count as the menu bar icon; cleared at 0; Settings > Notifications & tray > Dock badge turns it off)
- Settings > About: links to the Website, “Buy me a coffee” (the support page) and the Source code
- Signing in to Google or Microsoft has a Cancel button (mail and calendar); it stops waiting at once and nothing is added. If a Microsoft sign-in ends without access, Hey Look! suggests asking your IT admin to approve it

### Changed

- Mail is shown on its original background in every theme (the colours its sender chose), also in the dark theme, where 1.0.0 recoloured it dark. Use the new button to get the dark version
- Sign-in with Google: Google has not finished reviewing Hey Look! yet, so its sign-in page may say “Google hasn’t verified this app”: choose Advanced, then Go to Hey Look! (unsafe). Hey Look! says so while it waits. Until the review is done, Sign in with Google and Google calendar sync are limited to the first 100 people; when Google blocks a sign-in Hey Look! explains it and offers to add Gmail with an app password instead
- Behind the scenes: the release process is ready to sign and notarise the macOS app and checks every update signature before a release is published. Nothing changes for you until Apple signing is switched on

### Fixed

- A Google or Microsoft mailbox whose sign-in ended (access removed, password changed) failed quietly; it now shows “Sign in again” in the folder list and in Settings
- After a manually added IMAP account had downloaded its mail, “Downloading mails… 100 / 500” could stay on screen for good; it now disappears when the download ends
- Calendar: in an event’s … menu, clicking Edit, Duplicate or Delete with the mouse did nothing (since 1.0.0; the keyboard worked)
- Calendar: the start and end rows of the New event dialog are aligned
- An outgoing (SMTP) server that accepts a connection but never answers the secure handshake could keep Hey Look! waiting for good when you added an account or sent mail; it now gives up after at most 30 seconds and shows the secure-connection hint
- Add account no longer saves a mailbox whose SMTP server cannot be secured (the secure-connection hint now really stops the add)
- A mail server that answers unexpectedly to IDLE or to selecting a folder can no longer stop the app
- A Google sign-in that Google blocks no longer ends with an empty red box; it explains what happened. A blocked calendar no longer offers “Allow access again” when an administrator has to approve it, and calendar sync errors are shown in plain words with the details on a separate line

## 1.0.0 — 2026-10-14

First public release of Hey Look!, a fast, private desktop mail client.

- Many mailboxes in one place: Google and Microsoft (OAuth), iCloud, Yahoo and any IMAP/SMTP server
- Conversations, snooze, pin, flag, undo for archive/delete/junk, undo send and send later
- Search with filters and operators, Focused/Other inbox, Sweep (clean up by sender), filters
- Calendar invitations (accept/tentative/decline) and a local calendar (month, week and agenda views, reminders, `.ics` import and export); syncing with other calendar services may come in a later update
- OpenPGP encryption and signing
- Optional AI Assistant with any OpenAI-compatible endpoint
- Tray icon with unread badge and native notifications (Windows with action buttons, Linux without, macOS none in this version)
- New: Hey Look! updates itself. When a new version is out, agree once, keep working while it downloads, and the app restarts into the new version (it asks first while you are writing)
- Linux: links and attachments open through the desktop's `xdg-open` (then `gio`, `sensible-browser`) with the AppImage's own library paths removed, and a link or file that cannot be opened is reported instead of nothing happening; "Send test" reports a missing notification service
- Not tested on the release build (planned for 1.0.1 testing): Windows tray Quit while a message is in its Undo time, the installer run over a running app, link and attachment opening on Windows; on macOS the first-start steps and log out / restart with the app running.
- Linux new-mail notifications were verified on WSLg with dunst; behaviour with a minimised window was not verified.
