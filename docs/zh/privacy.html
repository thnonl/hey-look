我们是谁

Hey Look! 是免费的开源软件（MIT许可证），由名为thnonl的开发者（“我们”）发布。联系方式：namth.onl@gmail.com。

简而言之

Hey Look! 在你的电脑上运行，并直接与你的邮件服务商通信。我们不为这款应用运营服务器。我们不会接收、收集或存储你的邮件、日历、联系人、密码或登录令牌，应用中也不含任何分析、广告或遥测代码。

1. 应用在你的电脑上存储的数据

数据存放位置
你的邮件和文件夹的副本、从你的邮件中提取、用于提供收件人建议的地址、日历事件（你自己的事件，以及开启了日历同步的邮箱中你所选日历的事件）、设置、规则、签名、模板、OpenPGP密钥（私钥仅以受密码短语保护的形式保存）位于你的用户数据文件夹中的本地数据库：Windows为%APPDATA%\thnonl.heylook\，macOS为~/Library/Application Support/thnonl.heylook/，Linux为~/.local/share/thnonl.heylook/
密码、OAuth刷新令牌、开启了日历同步的邮箱的日历登录令牌、你的AI密钥、OAuth客户端密钥你系统的凭据存储：Windows凭据管理器、macOS钥匙串，或Linux上的Secret Service（GNOME Keyring、KWallet），条目名称形如heylook…（日历登录令牌是单独的一个条目，名称以:calendar结尾）
不含邮件内容的技术性启动日志同一数据文件夹中的startup.log

访问令牌和你打开的附件在本次会话期间保存在内存或临时文件夹中。这些数据由你电脑自身的账户和磁盘保护机制来保护；请确保你的电脑安全。

2. 应用连接到哪些服务器

目的地时间发送的内容
你的邮件服务器（IMAP、SMTP）用于同步、发送和整理邮件你的登录信息（密码或OAuth令牌）以及你执行的邮件操作
Google登录（accounts.google.com、oauth2.googleapis.com）和Microsoft登录（login.microsoftonline.com）添加Google或Microsoft账户时、为其开启日历同步时，以及续期登录时登录请求。你在浏览器中服务商自己的页面上登录
Google日历（www.googleapis.com）和Microsoft Graph（graph.microsoft.com）仅限你开启了日历同步的邮箱：用于下载其日历，以及保存你添加、修改、删除或回复的事件你的日历登录令牌以及你对事件所做的更改
你的邮件域名的autoconfig地址、Thunderbird ISPDB（autoconfig.thunderbird.net）以及DNS查询仅在你点击检测设置时你的地址所属的域名（你自己域名的autoconfig也会收到该地址）。绝不会发送你的密码
你配置的AI端点（可选）仅在你要求总结、翻译或使用“用AI撰写”时相关邮件或草稿的文字以及你的指令（见第5节）
邮件中提到的服务器仅在你允许加载远程图片，或在订阅邮件上点击取消订阅时来自你电脑的普通网络请求。对于你允许加载的图片，应用会尽量自己下载；对于它无法下载的图片，邮件视图可能会直接请求，这时发件人能看到该请求
github.com用于检查是否有新版本（在启动时以及应用从托盘恢复时，最多每6小时一次；可在“设置”的“关于”中关闭），以及下载你同意安装的更新对最新版本文件的请求。GitHub能看到你的IP地址。你的邮件和账户信息绝不会被发送

你打开的链接会交给你的浏览器；你打开的文件会交给系统用来打开它们的应用。这些服务和应用不受我们控制。

3. Google用户数据

如果你添加Google账户，Hey Look! 会请求：

  • https://mail.google.com/：通过IMAP和SMTP读取、发送、整理和删除你的Gmail邮件。对于IMAP和SMTP，Google没有提供范围更窄的权限。
  • openid、email、profile：用于获知你所登录账户的地址和名称。
  • https://www.googleapis.com/auth/calendar.events：仅在你为某个Google邮箱开启日历同步时请求，用于显示你所选日历中的事件，并把你添加、修改、删除的事件以及你对邀请的回复保存到Google日历。
  • https://www.googleapis.com/auth/calendar.calendarlist.readonly：随日历同步一并请求，用于列出你的日历，以便你选择要同步哪些。该列表绝不会被更改。

日历权限是单独的请求，只在你开启日历同步时才会发出；如果你从不开启，Hey Look! 绝不会向Google请求这些权限。

用途：仅用于在你的电脑上提供你在应用中看到的邮件和日历功能。日历数据绝不会发送给AI助手。存储：见第1节。共享：我们从不接收这些数据，也不出售、共享或转让这些数据。应用只会把Google数据发送给Google（你的邮箱，以及开启日历同步后的日历）；如果你使用可选的AI助手，则会把你选择处理的邮件文字发送给你配置的AI端点（第5节）。参与 Hey Look! 的任何人都不会阅读你的邮件或日历。Google数据不会用于广告，我们也不会用它来创建、训练或改进AI或机器学习模型。

Hey Look! 对从Google API获得的信息的使用，将遵守Google API Services User Data Policy（Google API服务用户数据政策），包括其中的Limited Use（有限使用）要求。这也包括通过Google日历API获得的日历信息。详情：Google API数据使用。

4. Microsoft账户数据

如果你添加Microsoft账户，Hey Look! 会请求IMAP.AccessAsUser.All、SMTP.Send、offline_access、openid、email和profile，其用途与第3节相同。开启日历同步后，Hey Look! 还会为该邮箱另行请求Calendars.ReadWrite（Microsoft Graph），其用途与第3节中的Google日历权限相同：显示你自己日历中的事件，并保存你添加、修改、删除的事件以及你对邀请的回复。他人与你共享的日历不会被读取。

5. AI助手（可选，设置之前处于关闭状态）

端点（任何兼容OpenAI的服务，或你自己网络中的服务器）及其密钥都由你选择。只有当你点击按钮要求总结、翻译或“用AI撰写”时，Hey Look! 才会向它发送文字：总结最多发送该对话中可读邮件的24,000个字符，翻译最多发送该邮件的12,000个字符，写作辅助则发送你的草稿、主题，回复邮件时还会发送你所回复邮件的最多6,000个字符。助手读取的是邮件的可读文字，所以如果你就此提问，解密后的OpenPGP内容也会被发送。该服务收到的内容适用其自身的条款和隐私政策，我们无法控制。将端点留空即可保持该功能关闭。

6. 本网站

没有Cookie，没有分析工具，也没有第三方脚本、字体或嵌入内容，除非你要求加载Ko-fi小组件（见下文）。本网站托管在GitHub Pages上；GitHub会处理你的IP地址等技术数据以提供页面，适用GitHub自己的隐私声明。你用页眉中的按钮所做的主题和动画选择仅保存在你的浏览器中。“支持”页面可以加载Ko-fi小组件（来自ko-fi.com的嵌入页面，以及来自storage.ko-fi.com的Ko-fi小组件脚本和图片），但只有在你点击要求加载它的按钮之后才会加载；之后适用Ko-fi自己的政策。如果你不点击，就不会加载任何来自Ko-fi的内容。该页面还显示一张银行转账二维码图片，它是本网站上的一个文件。

7. 数据的保留与删除

数据会一直保存在你的电脑上，直到你将其删除。应用对每个邮箱最多保留你所设定数量的邮件（默认2,000封），并且只会从这台电脑上移除较旧的副本；它们仍留在你的服务器上。

  • 移除账户：设置 > 邮箱 >（账户）> 移除账户会删除该邮箱的本地副本及其保存的凭据。邮件仍留在服务器上。
  • 关闭日历同步：设置 > 邮箱 >（账户）> 日历 > 与Google同步日历（或Microsoft）。日历和事件会从这台电脑上移除，日历令牌也会被删除；它们仍保留在你的服务商那里。
  • 移除AI密钥：设置 > AI助手 > 移除已保存的密钥。
  • 清除所有内容：先移除你的账户，卸载 Hey Look!，然后删除第1节中提到的数据文件夹，以及凭据存储中残留的所有heylook…条目。
  • 在服务商处撤销访问权限：Google请访问myaccount.google.com/permissions；Microsoft请在你的Microsoft账户的应用权限中撤销，或通过你所在的组织撤销。

我们不持有你的数据的任何副本，因此我们没有什么可删除的；欢迎通过namth.onl@gmail.com向我们提问。

8. 安全

与邮件服务器的连接要求使用SSL/TLS或STARTTLS，登录使用带PKCE的OAuth 2.0，密码和令牌保存在系统的凭据存储中（OpenPGP私钥保存在应用的数据库中，由你的密码短语加锁），更新会对照应用内置的签名进行校验。没有任何软件是毫无缺陷的；我们不能保证应用或你的数据没有安全风险（参见服务条款和安全）。

9. 儿童

Hey Look! 不面向13岁以下的儿童（或其所在国家/地区规定的同意年龄下限以下的儿童）。如上所述，我们不会有意收集任何人的数据。

10. 你的权利

由于我们不收集也不持有你的个人数据，访问、更正或删除数据的请求可通过应用自身的控制项（第7节）和你的邮件服务商来完成。你所在地的数据保护机构仍然可供你求助。

11. 变更

我们会在此发布变更，并注明新的生效日期。如果应用开始以新的方式使用Google用户数据，会先在应用内征求你的同意。
