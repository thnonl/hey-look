Hey Look!如何保护您

  • Hey Look! 通过加密连接（TLS 或 STARTTLS）连接您的邮件服务器。只提供未加密连接的服务器无法添加。
  • Google 和 Microsoft 登录在您的浏览器中、在它们自己的页面上完成（带 PKCE 的 OAuth 2.0）。应用保存的是登录令牌，而不是您的密码。
  • 密码、登录令牌和您的 AI 密钥保存在系统的密码存储中。OpenPGP 私钥保存在应用的数据库中，由您的密码短语保护。
  • 显示邮件时，不会运行邮件里的任何脚本或表单。
  • 图片在您允许之前一直隐藏，所以隐藏的图片无法告诉发件人您打开了邮件。
  • 来自您写过信的人和知名服务的图片可以自动显示，但只限于通过发件人验证的邮件（发件人域名的 DKIM 或 DMARC）。垃圾邮件、加密邮件、您写过信的人发来的邮件列表邮件或订阅邮件中，以及验证失败时，图片从不自动显示。您可以为某个发件人关闭自动显示，也可以在“设置 > 邮箱 > 阅读与同步”中为所有邮件关闭。
  • 打开程序或脚本附件之前，以及打开显示的网址与实际网址不同的链接之前，Hey Look! 都会先询问您。这不是完整的钓鱼检测。
  • 信任服务器证书的选项默认关闭。如果您为某个账户打开它，Hey Look! 就不再检查该服务器的证书。
  • 从网页粘贴的文字会被清理，写邮件时也不会加载任何图片。

更新经过签名

Hey Look! 只从项目在 GitHub 上发布的版本中下载更新，并且只有当更新的签名与项目的密钥相符时才会安装；这个密钥内置在应用里。在您同意之前，不会下载或安装任何内容。在 Windows 上，.msi 随后会要求管理员权限；在 Linux 上，.deb 和 .rpm 会要求输入您的密码。

安装程序尚未签名

Windows SmartScreen 和 macOS Gatekeeper 可能会在您第一次打开应用时发出警告，因为安装程序没有使用发布者证书签名，Apple 也没有为 macOS 应用做公证。下载页面说明了如何打开。

报告漏洞

请通过GitHub私下报告安全问题：打开github.com/thnonl/hey-look/security并选择“Report a vulnerability”（报告漏洞）。请不要公开提交议题。您也可以发邮件到namth.onl@gmail.com。

已知限制

  • 如果您的邮件服务商没有在邮件中记录发件人验证的结果，伪造的邮件可能会更改或取消您收到的日历事件，或者让其中的图片自动显示。可疑链接，以及程序和脚本附件，仍会先询问您。
  • OpenPGP 还没有与其他 OpenPGP 应用一起测试过。
  • 您设置的 AI 服务会收到您询问的文字，包括解密后的 OpenPGP 邮件。
  • “没有分析”这一说法依据的是源代码，而不是网络测试。
  • 没有做过独立的安全审计。
  • “机密”邮件只在 Windows 和 macOS 上对截图隐藏，而且任何办法都无法阻止有人用相机拍下屏幕。
